# B：展示意图判断

B根据视觉行为和语音证据，判断讲解者是否正在主动展示物品，并确定镜头需要关注的目标。输入是A生成的逐帧感知包和D生成的语音事件；输出是与媒体时间对齐的状态序列。视觉负责目标定位和动作证据，语音帮助确认展示语境。

## 从候选物品到展示状态

系统首先寻找与手有关联的物体，再结合物体相对支撑面的抬升、运动稳定性和展示区域判断形成候选。候选证据持续满足要求后进入SHOWING，输出目标轨迹ID。短时遮挡通过交互记忆维持；持续丢失、放下或展示结束使状态退出。

每个感知包按timestamp_ms更新一次。持续时间均以毫秒计算，不将包序号当作固定帧率。核心配置位于configs/presentation_intent.json：候选确认300ms，展示确认600ms，目标丢失容忍600ms，放下确认100ms，展示退出600ms。边界和物体轨迹的稳定性也会影响实际切换时刻。

实现以RecoveryOnlyIntentStateMachine为入口，视觉路径使用SparseVisualIntentStateMachine。视觉路径保存短时手部运动与交互历史，使遮挡后出现的物体仍能结合已有抬起证据判断。

## 拿着物品与主动展示

物品离开桌面并不足以说明正在展示。B以人物框为参考，检查两侧是否同时存在低位物品：物体位于人物框外侧四分之一、高度下部28%，且高于靠近人物框底部的桌面区域。符合双侧低位持物姿态时，低位目标不能提供有效抬起证据，语音也不能单独确认展示。

这一约束不依赖视频编号、时间段或物品类别。身前展示、单物侧面展示和双物举高仍按正常流程判断。没有检测到人物时，系统不猜测人体位置，继续使用其余视觉证据。这是几何判断，不能替代完整的人体动作理解。

## 语音如何参与判断

语音事件由语言解释器转为展示、介绍、属性、否定和结束等有限证据，经SpeechEvidenceBridge按时间提供给状态机。与当前目标相符的语句可以提前确认已经具备视觉基础的候选；没有可见目标、物品仍处于桌面区域或呈低位持物姿态时，语句本身不足以触发。

融合参数位于configs/semantic_priority_fusion.json。B不根据标注生成证据，标注只在预测完成后由评价器读取。语音解释和物体定位仍有各自的局限，不能将视听输出视为通用对话理解。

## 离线与延时流式

离线按完整媒体时间轴读取感知与语音，采用Faster-Whisper large-v3事件。延时流式按输入时钟接收数据，视觉与语音在独立进程运行，播放端缓冲6秒，只使用播放截止时已经可用的证据。

流式使用相同的展示证据和持物约束，以有限的时间容忍处理稀疏观测：观测间隔1250ms、证据间隙500ms、目标丢失1000ms、展示退出900ms；放下确认100ms、展示确认600ms。播放端状态过期容忍为1000ms。语音采用base CPU int8、beam 1、4秒窗口；增强视觉以10Hz采样，全帧与手部裁剪长边分别为1280和960。

固定缓冲能否持续维持取决于处理吞吐。模型预热单独进行，运行时还需检查帧完整性、排队和额外播放迟滞。B的受控回放用于复核触发判断；端到端实跑用于测量模型处理和播放时序，两者的评价范围见[流式说明](stream.md)。

## 三种模式与评价

纯视觉使用视觉状态机，不读取语音；纯语音只生成时间意图，没有目标定位框；视听使用相同感知输入并融合语音证据。三者在相同标注和评价时间轴上比较。

评价同时报告事件Precision、Recall、F1、展示时间覆盖率、非展示误触发时间和边界MAE。高覆盖率可能伴随展示事件合并，事件匹配正确也不代表边界完全准确。完整逐视频结果见[离线评价](offline.md)和[流式评价](stream.md)。

## 与C的交接

逐帧输出包括timestamp_ms、state、target_id、score和reason_codes。C从同一次A运行中查找target_id对应的物体框，再完成镜头裁剪、缩放和平滑。轨迹ID不能跨模型运行混用；非SHOWING状态保持全景。B负责何时关注哪个目标，不决定最终缩放倍率与构图。

缓存重放命令：

```bash
python -m scripts.run_refined_b --out outputs/new_replay
```

输入位于outputs/cache，输出包含纯视觉、纯语音、视听序列及评价。完整模型运行与流式命令见根目录README。
