# A 检测改进候选：人工复核入口

候选为 yolo11s.pt，基线为 yolo11n.pt。均使用 imgsz=1280、conf=0.35。尚未替换正式默认模型。

`scripts/a_sequence_compare.py` 生成 `outputs/a_sequence_compare/` 中的短片。左为 nano 基线，右为 small 候选，均由同一原始帧重新推理，使用相同 SimpleObjectTracker。每秒采样 5 帧，以 5 FPS 播放；它不是完整 30 FPS 追踪评测，也不是实时速度测试。追踪器 max_missed=1，仅用于这次相同条件的对照。两侧 ID 独立生成，不能跨左右比较编号是否相同。

画面仅展示下半部手物区域并缩放以读清文字。原始视频及原有 JSONL 不变。对照检测明细保存在 detections.json。

| 视频 | 原片范围 | 复核重点 |
|---|---|---|
| B03_compare.mp4 | 0–12 秒 | 两只手的苹果是否更少漏框；多个苹果的大合框是否减少 |
| C01_compare.mp4 | 2–14 秒 | 拿起时是否检出；托在手里是否持续有框；是否误框几个苹果 |
| C03_compare.mp4 | 3–17 秒 | 遮挡后是否仍跟原橘子；是否错接其他橘子 |

分别判断右侧比左侧：更好 / 相当 / 更差。问题记录显示的原片时间。仅比较“框住同一物体时 ID 是否持续”，不比较左右具体 ID 数字。完全遮挡时没有框可以接受；露出后长时间没有框、跳到另一颗水果、大框覆盖多个水果需要记录。

B03 第6秒的初步目检：small 1280/.35 检出了双手苹果，nano 当前配置漏检。静态样例不足以确定时间稳定性，需要观看短片后才能决定配置。

此前 A02 正常；B03/C02 有合框和断续；C03 用户确认 obj_8→obj_10，未串到其他橘子；C01 用户确认同一苹果多次换 ID，未观察到 ID 转给其他苹果。这些都是开发反馈，不是独立测试集精度或 ID-switch 指标。
