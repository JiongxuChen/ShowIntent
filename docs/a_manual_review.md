# A 模块人工验收（约 3 分钟）

打开外层项目目录 `outputs` 中的 `perception_*_overlay.mp4`。这是带检测框的原画面，而不是 C 的裁剪预览。绿色框是物体，蓝色框是手；物体文字包含类别、ID、置信度。

## 逐段检查

| 文件 | 看哪里 | 要记录什么 |
|---|---|---|
| perception_A02_overlay.mp4 | 全片约 18 秒，特别看举起、展示、放下 | 橘子框是否跟随实际橘子；手框是否贴手；人物是否正立；记下框消失或跳到其他水果的时间 |
| perception_B03_overlay.mp4 | 全片约 13 秒，重点看手遮挡苹果时 | 同一个苹果是否突然换 ID；框是否跳到背景。这里有框和 relation 本身正常，A 不负责决定是否特写 |
| perception_C02_overlay.mp4 | 全片约 29 秒，苹果换橘子时暂停 | apple/orange 是否正确；同类多个水果是否串 ID；分别记旧 ID、新 ID和时间 |
| perception_C03_overlay.mp4 | 全片约 20 秒，遮挡前后暂停 | 被展示橘子在遮挡后是否仍有框，ID 是否更换或跳到桌上其他橘子 |
| perception_C01_overlay.mp4 | 全片约 18 秒，苹果特写时 | 大框是否覆盖完整苹果；ID 是否反复变更；区别换 ID 与框跳到另一个苹果 |

## 反馈模板

每个问题填写一行即可，不需要标注每帧：

```text
视频：C03
时间：00:__–00:__
问题：漏框 / 框错物体 / ID 更换 / ID 串物 / 手框错位 / 画面方向错误
观察：同一个橘子遮挡后，ID 从 obj_? 变成 obj_?。
是否影响使用：明显 / 轻微 / 不确定
```

没发现问题时写：`A02：方向正常，手框和水果框贴合，未见明显错框。`

## 判断标准

- 可接受限制：短暂遮挡漏框、同一物体更换 ID（需记录，不能据此声称跨遮挡追踪稳定）。
- 必须修复：整体坐标错位、画面方向错误、长时间把背景框成果实、物体可见时持续没有框、ID 跳到另一件物体导致下游错选。
- 橘子显示 orange 是预训练模型类别名，属于预期结果。
- 单靠多个 ID 的数量不能计算 ID 切换率；多实例场景需要人工确认物理上是否为同一个物体。
