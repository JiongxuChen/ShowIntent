# B 的评价说明

目前的结果用于发现开发问题，正式事件评价还需要人工标注。12 条素材已用于调参和回归，不能据此报告未见数据上的准确率。

## 已经检查的内容

模拟输入验证状态流转、跨类别选择、普通持物和搬运抑制、目标丢失、短时重关联，以及不同采样率下的时间行为。它们用于检查工程规则，不代表真实识别效果。

真实感知回放使用 A 对 12 条视频生成的完整 JSONL，共 7,637 个包。B 主方法和 Pick-up 基线读取相同输入，不接收视频编号对应的场景标签。9 条正例均在抽帧复核的展示区间内出现过正确类别触发，B01、B02、B03 三条负例没有 SHOWING。

`evaluation/development_review.csv` 保存抽帧初检选取的核心区间，全部仍为 `NEEDS_HUMAN_REVIEW`。正区间共 106 秒，负区间共 94.546 秒；刻意排除了部分动作过渡，不能作为精确事件边界或物理实例真值。

在这些区间上，主方法的正确类别展示覆盖约为 83.6%，各正例视频平均约为 75.0%；已选负区间内没有 SHOWING。这里的覆盖是“B 为 SHOWING 且目标类别符合”的时间占比，不是准确率，也不是同类实例选对率。A03 和 C01 的覆盖分别约为 33% 和 32%，存在明显中断和漏触发。

| 开发核心区间指标 | 主方法 | Pick-up 对照 |
|---|---:|---:|
| 正区间正确类别展示覆盖 | 83.6% | 24.9% |
| 至少出现一次正确类别触发的正区间 | 12 / 12 | 3 / 12 |

12 个正区间来自 9 条正例视频；长片段可包含多个展示区间。表格只描述这份待复核的开发区间，不意味着完整视频没有误触发。

## 复现开发区间检查

准备 `data/perception/perception_<编号>.jsonl` 后，在仓库根目录运行：

```bash
python -m src.intent.replay_real --perception-dir data/perception --out outputs/intent_batch
python -m src.intent.evaluate_review --perception-dir data/perception --replay-dir outputs/intent_batch --out outputs/review_metrics.json
```

批量回放会同时生成主方法和 Pick-up 对照。评价脚本按相邻感知包的媒体时间间隔加权，不按帧数计数；不外推最后一个包之后的时间。标签只在推理结束后用于评分。复跑时更换回放输出目录。

若只回放了部分视频，应通过 `--review` 提供包含相应视频的 CSV。不要将缺少视频结果的报告当作完整评价。

## 正式评价需要补齐的内容

`annotations.csv`、`track_mapping.csv`、`split_manifest.csv` 当前只有表头，`annotation_queue.csv` 只列素材与元数据。按 [标注规范](../evaluation/annotation_guidelines.md) 完成以下工作：

1. 不参考 B 输出，标出展示与非展示事件的起止；无法确定的区间保留不确定标签。
2. 为同类物体分配物理实例编号，再记录 A 的跟踪 ID 与实例之间的分段映射。
3. 交叉复核边界与争议，按参与者或录制会话划分后续独立数据。
4. 固定容忍窗口和匹配规则，再比较主方法、Pick-up 及未来的语音融合方法。

正式报告应分别呈现事件召回与误触发、触发和结束时间偏差、展示覆盖与碎片化、实例选择错误。C 的镜头构图与观看效果单独验收，不能由 B 的状态覆盖替代。
