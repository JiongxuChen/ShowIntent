# 闭集视觉模型对比结果

本实验四个模型均完成14段视频：11段水果、3段书籍，A04不参与。每个模型处理12,640帧。112个阶段检查点的产物哈希、运行时记录的代码/配置/数据清单哈希，以及全部感知时间戳均通过核查。没有重新运行语音识别，也没有调整各模型的B参数或阈值。

**结论：更换检测器能改善部分场景，但没有一个模型在全部指标上占优。建议保留YOLO11m为现有基线，把RT-DETR-L作为下一步重点候选；先复核物品选择和定位，再决定是否替换默认模型。**

| 模型 | TP / FP / FN | 事件F1 | 展示时间覆盖率 | 非展示误触发时间 |

水果组中，YOLO11m的事件F1最高；RT-DETR-L覆盖率最高，但D01多出碎片或额外触发事件。YOLO11l的非展示误触发时间最少，却有两个额外事件：事件数量和持续时间应同时看，不能只按其中一个选模型。四个模型在B01、B02、B03三个纯负例视频上均未触发。

书籍组中，RT-DETR-L与YOLO11n均匹配到全部10个展示事件，但RT-DETR-L覆盖率明显更高。相较YOLO11m，RT-DETR-L覆盖率从85.89%提升到96.17%，增加10.28个百分点，同时非展示误触发从10.981秒增加到15.579秒。YOLO11n虽然事件F1为1.000，覆盖率只有88.67%，说明“事件被检测到”和“整段展示持续被覆盖”是两件事。

事件F1为1.000不等于完美：只要事件与真值达到匹配阈值，就可能仍然存在进入偏晚、退出偏晚、选错物品等问题。非展示误触发秒数包括匹配事件伸出标注边界的部分，即使FP事件数为0，也可能有非零误触发时间。

## 下一步建议与结论边界

1. 保留YOLO11m默认配置；保存四组完整结果，不立即重新训练或调整阈值。
2. 优先复核RT-DETR-L与YOLO11m的物品选择和框：书籍183631、183847，以及多目标D01。新模型的track_id不能沿用旧映射；每个模型目录下的track_mapping.csv目前仍是PENDING。完成映射后再计算实例F1和正确目标覆盖率。
3. 在新采集场景上沿用固定流程比较，观察RT-DETR-L的覆盖率优势能否保持。按录制场次划分数据，并补充“拿着但不展示”“收拾归位”等负例，不根据这3段书籍反复选阈值。
4. 如进一步改善语音，应以新增的独立正负例和净收益为验收依据，同时报告覆盖增加与误触发代价；本实验没有调整稳定融合逻辑。

本实验是固定适配流程下的端到端触发对比，不是检测mAP排名。没有逐帧检测框真值，新模型身份映射也未完成。14段小样本不支持统计显著性或广泛泛化结论。更大的YOLO不保证更好，固定阈值也不等于各模型各自最优。


# 水杯与饮料：四模型对比结果

**当前流程下继续保留YOLO11m作为默认更合适。** 它在8段新场景中匹配9/10个展示事件，额外事件为0；YOLO11l其次。RT-DETR-L虽然时间覆盖率最高，三杯视频却持续指向已放下的大杯，不能把高覆盖率当作效果最好。

## 运行核验

四个模型均完成8段视频，每个模型7,124帧，共64个感知/回放阶段检查点。记录的代码、配置、数据清单及阶段输出哈希、全部感知PTS均核查通过。四模型使用的语言观察完全一致；YOLO11m三种方法的逐帧预测与此前修复版结果一致。

所有模型共用persistent修复版B、3000毫秒候选交互记忆、相同视觉参数和ASR；没有重新转写、调阈值、改标签或针对模型定制B规则。

## 水杯是主要分歧

- **YOLO11m：** 单杯171237覆盖85.22%，连续触发；三杯171527仍漏第一个黑盖大杯，但米色杯与图案小杯均匹配，没有碎片额外事件。
- **YOLO11l：** 单杯171237只触发2.999–10.689秒，覆盖54.15%；三杯片仍漏黑盖大杯，米色杯中间有66毫秒断开，带来一个额外时间事件。
- **YOLO11n：** 单杯只短暂触发3.517–6.689秒，覆盖22.34%，未达到0.3事件IoU；三杯片有碎片和放下后额外触发。部分时间匹配还存在选错杯的问题。
- **RT-DETR-L：** 单杯覆盖85.22%；三杯片从6.366秒连续SHOWING到32.300秒片尾，覆盖真实展示时间90.67%，但没有退出、切换，三个独立真值事件均无法匹配。

RT-DETR-L的低F1并非简单等价于“什么都没有检测到”。它在8秒时正确指向拿起的黑盖大杯，随后保持同一item_19；18、28秒操作者正在展示另外的杯子，它仍指向桌上已放下的黑盖杯。15、24、31秒等时刻该目标还短暂没有对应检测框。

YOLO11n在15、18秒也指向桌面的黑盖杯，而非正在展示的米色杯。因此时间F1和时间覆盖率仍可能高估正确物品效果，不能把类别相同当作目标正确。

原图叠框抽查见 水杯目标对照图（历史材料未随本次发布提供）：每行依次为YOLO11m、RT-DETR-L、YOLO11n，列为8、15、18、28秒。绿色为实际SHOWING目标。

### RT-DETR-L的退出失败来自哪里

用已保存感知重放纯视觉诊断，item_19的B高度基准anchor_y为0.8582；放回桌面后杯中心约0.684。B仍认定它高于基准、处于抬起状态，持续保持。这个记录与原图中“杯已在桌上、镜头目标不退出”一致。

这说明修复版的保持机制仍依赖高度基准的可靠性；场景高度、冷启动或检测框变化导致基准不合适时，会把已放回的物品误当仍在展示。现有事实足以定位这条失败链，但没有进一步消融每一次基准更新，不能把全部责任归到检测器或某一行逻辑。原始诊断在rtdetr_cup_diagnostic.json。

| 模型 | 水杯覆盖率：纯视觉 → 视听 | 饮料覆盖率：纯视觉 → 视听 | 总体F1：纯视觉 → 视听 | 总体非展示触发秒数：纯视觉 → 视听 |
|---|---:|---:|---:|---:|
| yolo11n | 32.56% → 44.61% | 82.86% → 84.65% | 0.800 → 0.762 | 8.664 → 8.981 |
| yolo11m | 68.86% → 68.86% | 83.34% → 87.44% | 0.947 → 0.947 | 7.363 → 7.597 |
| yolo11l | 52.27% → 55.39% | 82.92% → 88.28% | 0.900 → 0.900 | 7.948 → 7.948 |
| rtdetr-l | 88.41% → 88.41% | 84.05% → 85.90% | 0.778 → 0.778 | 13.829 → 14.929 |

饮料组四个模型均有时间覆盖增益：YOLO11n约+1.79、YOLO11m约+4.11、YOLO11l约+5.36、RT-DETR-L约+1.84个百分点。YOLO11l没有增加非展示触发秒数，YOLO11m仅增加0.100秒；RT-DETR-L增加1.100秒，代价较大。

但本实验没有哪个模型因语音增加了匹配到的展示事件数。YOLO11n虽增加时间覆盖，却多了一个不够长、无法匹配的短触发，事件F1下降。并且存在选错杯的例子，所以这些增益只能称时间覆盖增益，尚不能都称为正确物品展示的提升。

结论是：当前语言在饮料场景中有可复现的辅助作用，主要改善部分触发时机；它无法自动补救错误实例绑定、放回判断错误和不稳定检测。没有证据支持“换检测器后视听就明显优于纯视觉”，也没有必要为增大语音相对收益而刻意选择较差的视觉模型。

## 选择与下一步

当前继续使用YOLO11m。YOLO11l在饮料中略有覆盖优势，水杯中却更容易提前结束或断开；YOLO11n还有选错物品和碎片问题。RT-DETR-L能识别并启动黑盖大杯，值得作为后续验证对象，但应先解决保持和退出对高度基准的依赖，再重新评价。

后续若修改B，重点是让目标自己的桌面位置/下降趋势和轨迹几何约束参与退出，防止不合适的高度基准使保持一直续约。需用相同改法回测所有检测器，并保留本实验数字；不能针对RT-DETR单独加视频规则。

本实验没有更改默认模型、触发规则、标签或参数，仅完成核查、诊断和报告。原始YOLO11m修复结果仍保留。

## 运行模型对比

先将原视频和相应模型放到README规定的目录。缓存ASR由outputs/cache提供。不同模型使用相同场景、标签和参数，对比报告保留各自的B配置口径，不能将两组数字直接混合排名。

```bash
python -m scripts.download_closed_set_models
python -m scripts.run_closed_set_benchmark --collections fruit --out outputs/new_fruit
python -m scripts.run_closed_set_benchmark --collections cups --intent-profile persistent --out outputs/new_cups
```

需要新输出目录；中断后保持参数不变并添加--resume。运行需要GPU和原视频；已发布的评价JSON不需要重新推理即可查看。

books、drinks同样按场景单独运行：将--collections分别改为books或drinks，且使用不同输出目录；drinks使用persistent配置。
