# 成员 D 人工参考开发评测

本轮使用已由用户独立审听并提交的 D01、A03、A04、A01、B01，共 125.888 秒开发素材。5/5 参考通过人工确认与完整覆盖校验；三种模式均重新执行，15/15 运行可评分，跨模式共同案例为全部五段。完整台词、复核人信息和原始音视频保留在本机。

## 同配置对照

固定 Systran Faster-Whisper base revision `ebe41f70d5b6dfa9166e2c581c45c9c0cfc57b66`、中文 `zh`、CPU int8、4 线程、beam 3、当前同一词表与噪声过滤策略。固定窗口为 4000 ms；增量输入步长为 2000 ms，缓存上限 15000 ms。参考文字不进入识别或提示词。

| 模式 | 原字形 CER | 简繁归一 CER | 类别 F1 | 语言线索 F1 | 发布时仍在 3 秒 TTL 内的类别事件 |
|---|---:|---:|---:|---:|---:|
| 离线 | 39.31% | 13.19% | 0.897 | 0.273 | 1/12 |
| 固定窗口因果 | 27.97% | 17.94% | 0.741 | 0.227 | 10/10 |
| LocalAgreement 增量确认 | 31.13% | 9.23% | 0.643 | 0.140 | 6/11 |

CER 按全部 379 个参考字微平均，含无语音片段中的额外输出；简繁归一指标单列，未替代原字形结果。类别与语言线索按人工发话区间的最大重叠匹配统计，ASR 分段与人工分句不一致会影响 F1。TTL 统计只说明类别事件发布时的年龄，不保证类别正确、画面匹配或 B 会采用。

## 发现的问题

离线结果的多数类别事件已经过期：整段 EOF 后发布无法及时辅助前面的展示。固定窗口得到更多及时事件，但切词会损失转写内容。增量确认减少简繁归一后的文字错误，却未改善本轮区间级类别与线索匹配；D01 增量运行的计算 RTF 约为 0.684，确认等待仍会让一部分事件超过 TTL。RTF 不包括模型加载、解码和传输，不等于端到端延迟。

A03 三种模式均未发布文字。人工标为无语音的 A04 在离线模式发布了一段额外文字，固定窗口和增量模式没有发布。这是现有过滤策略仍会漏过的噪声误识别，不能把低音量自动等同于无语音。

语言线索召回较低，可能同时涉及有限词表、识别漏字和一条 ASR 事件跨越多条人工发话。下一步应分别核对这些原因；当前没有为这五段追加专用词表，也没有改写人工标签来提高分数。

## 复现与交接

在项目根目录运行：

```powershell
.\.venv\Scripts\python.exe scripts/run_verified_speech_benchmark.py
.\.venv\Scripts\python.exe scripts/export_verified_speech_summary.py
```

脚本在验证全部参考和来源哈希后才推理，使用独立 `outputs/verified_benchmark/` 保存新运行，原历史结果保留。再次执行会复用配置匹配且四类日志齐全的运行；配置变化或日志缺失会要求选择新目录。评测写入相邻 `outputs/verified_benchmark_evaluation/`。

可共享数值快照位于 [verified_speech_results.json](experiments/verified_speech_results.json)，采用显式字段清单导出，不包含台词、复核人或本机路径。快照含参考、事件与元数据哈希，具体区间问题仍须在本机私有报告中核查。
